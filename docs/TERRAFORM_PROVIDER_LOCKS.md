# Terraform provider lock-file procedure

> **Author:** Stan Zvenigorodskiy  
> **Organization:** DevOps Lab Inc.  
> **Website:** [DevOpsLabInc.com](https://DevOpsLabInc.com)

The repository contains three independent Terraform roots, so each root requires its own `.terraform.lock.hcl` file:

- `terraform/.terraform.lock.hcl`
- `terraform/global/bootstrap/.terraform.lock.hcl`
- `terraform/global/account/.terraform.lock.hcl`

Dependency lock files record the exact provider versions and signed package checksums selected by Terraform. They must be generated by Terraform against the provider registries; they must not be fabricated or copied between roots.

## Generate or refresh all lock files

Run this from an internet-connected, trusted workstation or CI runner using the Terraform version pinned by `.github/workflows/terraform.yml`:

```bash
./terraform/scripts/update-provider-locks.sh
```

The helper records checksums for Linux AMD64/ARM64 and macOS AMD64/ARM64 so local development and GitHub Actions use the same reviewed provider selections.

## Review before committing

1. Review the provider versions and signer information printed by Terraform.
2. Confirm each version satisfies the corresponding `required_providers` constraint.
3. Review the three lock-file diffs like application-code changes.
4. Commit the lock files with the Terraform configuration.
5. Do not run `terraform init -upgrade` during normal plans or applies; use it only in an intentional provider-upgrade change.

## Current package status

The audit environment could not access the Terraform Registry, so this package includes the generation helper and validation documentation but does not invent lock-file contents. Generate and commit all three lock files before the first production apply.
